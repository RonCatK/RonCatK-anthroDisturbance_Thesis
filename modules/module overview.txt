Module Overview

Purpose: Generates and updates anthropogenic disturbances over time using rates/sizes and potential layers; maintains a time-indexed “current disturbance” layer and writes optional diagnostics/exports. See modules_Testing/anthroDisturbance_Generator/anthroDisturbance_Generator.R (line 1).
Core outputs:
disturbanceList: nested list by sector/origin with both current and potential layers, updated each run.
currentDisturbanceLayer: per-year composite mask of all current disturbances for masking new picks and downstream use.
Execution mode:
Vector path: generateDisturbancesShp() produces true geometries with optional clustering/roads integration.
Raster path: generateDisturbances() produces pixel-aligned changes (faster, quantized).
Controlled by P(sim)$generatedDisturbanceAsRaster.
Integration Scope (SpaDES)

Upstream modules expected
Data prep for baseline and potentials: produces disturbanceList and (often) disturbanceParameters. The module warns and falls back to packaged NT example data if missing, meant only for testing. See .inputObjects defaults in modules_Testing/anthroDisturbance_Generator/anthroDisturbance_Generator.R (line 720).
Fire producer (optional): whichever fire module supplies rstCurrentBurn (binary burn raster) used when forestry is scheduled.
Downstream consumers
Any module needing updated disturbance layers or a per-year composite mask (currentDisturbanceLayer), e.g., forestry, habitat, or cumulative-effects analyses.
Scheduling integration
Module uses SpaDES event queue. It schedules four event types at the start tick (intended order: size → rate → generate → update), then reschedules “generate” and “update” every runInterval years. See doEvent() in modules_Testing/anthroDisturbance_Generator/anthroDisturbance_Generator.R (line 431).
Dependency Expectations

Required objects (normally supplied upstream; fallbacks exist for testing):
studyArea (SpatialPolygonDataFrame|SpatVector) and rasterToMatch (RasterLayer|SpatRaster), harmonized to the same CRS in init. See inputs: modules_Testing/anthroDisturbance_Generator/anthroDisturbance_Generator.R (line 360).
disturbanceList: nested list of current and potential layers by sector/origin (terra SpatVector preferred).
disturbanceParameters: table defining per-origin/type intervals, sizes, rates, geometries, and behavior flags.
Optional: rstCurrentBurn (fire raster), DisturbanceRate (table of rates), DEM and featuresToAvoid for roads/masking when enabled.
Optional fire integration
Couple the generator with a fire module that maintains rstCurrentBurn (e.g., historic or simulated burns) when forestry disturbances need to avoid recently burned stands.
For UA/rates harnesses there are two practical options:
  • Run `validation/ua/precompute_fire_masks.R` with a fire module (e.g., SCFM) to emit
    yearly `rstCurrentBurn_YYYY.tif` rasters, then point `UA_FIRE_MASK_DIR`
    (or `.inputFolderFireLayer`) at that cache (defaults to `data/synthetic/fire/`)
    so the generator can stream precomputed burns.
  • When legacy dependencies block SCFM, `validation/ua/generate_synthetic_fire_masks.R`
    can synthesize deterministic burn masks locally (tunable burn rate/cluster radius) that
    satisfy forestry scenarios until real outputs are available.
Packages
Core: SpaDES.core, terra, raster, data.table, sf, reproducible, stars, nngeo, digest.
Optional per-feature: roads (road connectivity), spaths/geodata (masking, DEM), foreach/doParallel (parallel clustering).

Vector geometry draw sequence: modules_Testing/anthroDisturbance_Generator/R/generateDisturbancesShp.R:640-864
1. Determine the interval quota: convert the per-year percent to area (`Rate <- disturbanceRate/100`) and multiply by study-area km² and `disturbanceInterval`; store as `expectedNewDisturbAreaSqM`.
2. Prepare candidates: dissolve potential polygons by `Potential`, erase overlaps with current disturbances, and trim the quota if the available potential is smaller.
3. Iterate through highest-potential features, sampling a footprint size from `disturbanceSize` (e.g., `msm::rtnorm(...)`). Clamp the sample to the remaining quota; if the sample still exceeds the quota, draw a Bernoulli with probability `quota/sample` and abandon the class when it returns 0.
4. Buffer/merge as required (lines are buffered to rectangles, enlarging uses growth steps) until the accumulated area reaches the quota or available potential is exhausted; record the achieved vs. requested percent for diagnostics.
5. For seismic lines, reuse cached clusters and length stats; for other classes the chosen polygons/lines are appended to the “current disturbance” layer and fed to connector routines.
Raster mode: generateDisturbances(...) returns:
individualLayers (mixed, may include SpatRaster)
currentDisturbanceLayer (list of SpatVectors with this-year additions). modules_Testing/anthroDisturbance_Generator/R/generateDisturbances.R:1
Raster generation loop: modules_Testing/anthroDisturbance_Generator/R/generateDisturbances.R:500-860
1. Convert the yearly percent to pixels (`expectedDistPixels <- (disturbanceRate/100) * totNPix * disturbanceInterval`). `totNPix` comes from the rasterToMatch extent; buffered-mode requests already account for future 500 m buffers.
2. If the quota is <1 pixel, fall back to a Bernoulli draw (`rbinom(1, 1, expectedDistPixelsProb)`), reducing the probability when buffers are required. A zero result aborts generation for that class.
3. Otherwise iterate, each pass selecting the highest-potential cells (`potLayF`) and expanding by `growthStepGenerating`; candidate pixels are accumulated until the chosen count meets the quota or available potential is exhausted. Progress is logged every few iterations.
4. When buffers are requested, newly chosen pixels are dilated to rectangular footprints; helper loops reduce overlap with existing disturbances and re-sample if too many buffered pixels spill outside the quota.
5. Final rasters are written into the `individualLayers` list; vector copies of the new pixels feed connecting routines and diagnostics, and percentage variance from the target is appended to `PercentageDisturbances_*.txt`.
Both backends merge existing “current” geometries into availability masks, erase overlaps with potentials, apply growth/generation math, and honor probability-based site selection when requested.
